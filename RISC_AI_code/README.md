# RISC_AI_code: RiSC-16 pipeline, kernel and tests

A 16-bit, five-stage pipelined RiSC-16 CPU with a two-entry TLB, user and kernel modes and precise exceptions, plus the small kernel and user programs that exercise it. The work is organised in five stages that follow the course testbenches.

```
./run_all.sh          # needs gcc, Icarus Verilog 12 (iverilog, vvp) and python3
```

`run_all.sh` builds the assembler, assembles every program, runs every stage and writes the logs. The last run's output is in [`logs/summary.txt`](logs/summary.txt):

| Stage | Testbench | Kernel | User program | Result |
|---|---|---|---|---|
| 1 | `test-i.v` | `sys-i.s` | `usr-i.s` | 11 cycles, every cycle matches `ref-phase1.log` |
| 2 | `test-ii.v` | `sys-ii.s` | `usr-ii.s` | 11 cycles, every cycle matches `ref-phase2.log` |
| 3 | `test-iii.v` | `sys-iii-iv.s` | `usr-iii.s` | 87 cycles, every cycle matches `ref-phase3.log` |
| 4 | `test-iv.v` | `sys-iii-iv.s` | `usr-iii.s` | 67 cycles, r1 = 0x2112 |
| 4 | `test-iv.v` | `sys-iii-iv.s` | `usr-iv-dmiss.s` | 347 cycles, r1-r6 = 1 2 3 4 0c00 0b00 |
| 4 | `test-iv.v` | `sys-iii-iv.s` | `usr-iv-imiss.s` | 371 cycles, r1-r6 = 1 2 3 4 a b |
| 5 | `test-BOOT.v` (`-DBOOT`) | `sys-iii-iv.s` | `rom-BOOT.s`, `usr-iii.s` | boot ROM loads the OS and enters user code; first 46 fetches match `BOOT-log.txt` |

## Folder layout

| Folder | Contents |
|---|---|
| `design/` | `RiSC.v` (pipeline, TLB, exceptions) and `memories.v` (memory, register files, PSR) |
| `assembler/` | `a.c`, the two-pass RiSC-16 assembler |
| `software/` | kernels (`sys-*.s`), user programs (`usr-*.s`) and the boot ROM (`rom-BOOT.s`) |
| `testbench/` | the course testbenches `test-i.v` … `test-iv.v` and `test-BOOT.v` |
| `images/` | assembled memory images (`*.hex`), regenerated by `run_all.sh` |
| `reference/` | Verilog-XL reference logs, `BOOT-log.txt`, and the course-provided memory images |
| `logs/` | output of the last run: a full log and an event timeline per stage, and `summary.txt` |
| `tools/` | `timeline.py`, which turns a simulation log into a list of exceptions, TLB writes and the halt |
| `docs/` | one document per step (below) |

## Reading the logs

Each `logs/<stage>.log` is the raw simulator output. Every clock cycle prints one block, from `------------- (time …)` down to the `TLB-B` line, showing every pipeline register; the course testbenches also dump the first four pages of memory. Each `logs/<stage>.timeline.txt` reduces this to the events that matter, for example:

```
cycle    time  event
    5      50  exc 0x51 user TLB miss            pc 0000 -> vector 0103
   15     150  exc 0x52 kernel TLB miss          pc 0108 -> vector 010e
   21     210  tlbw       asid 0: vpn c9 -> pfn 02
```
