# RISC_AI_code: RiSC-16, built up in four steps

A RiSC-16 CPU developed in four steps, each with its own design, test programs, testbenches, logs and README. Every step runs on its own; `run_all.sh` runs them all and writes [`summary.txt`](summary.txt).

```
./run_all.sh          # needs gcc, Icarus Verilog 12 (iverilog, vvp) and python3
```

| Step | Folder | Design | What it adds | Tests | Result |
|---|---|---|---|---|---|
| 1 | [`step1_simple/`](step1_simple/) | single-cycle CPU | the base instruction set, one instruction per clock | `prog.s`: every instruction, a loop, a load, a call | 28 cycles, all values correct |
| 2 | [`step2_pipeline/`](step2_pipeline/) | 5-stage pipeline | forwarding, load-use stall, branch squash | the same `prog.s` | 39 cycles, same results as step 1 |
| 3 | [`step3_tlb_kmiss/`](step3_tlb_kmiss/) | full `RiSC.v` | TLB, kernel mode, exceptions; kernel TLB-miss handler | 3a trap, 3b translation (course stages i, ii), 3c kernel miss | 3a, 3b match the reference logs on every cycle; 3c correct |
| 4 | [`step4_tlb_umiss/`](step4_tlb_umiss/) | full `RiSC.v` | user TLB-miss handler, with kernel misses nested inside it | 4a (course stage iii), 4b–4d (course stage iv) | 4a matches the reference log on every cycle; 4b–4d correct |
| extra | [`extras/boot/`](extras/boot/) | step 4, `-DBOOT` | reset into a boot ROM that loads the OS from disk | `rom-BOOT.s` | ROM runs and enters user code; needs a page-fault handler to finish |

## Layout

Each step folder has the same structure:

| Folder | Contents |
|---|---|
| `design/` | `RiSC.v` and `memories.v` for that step |
| `software/` | the assembly programs (kernel `sys-*.s`, user `usr-*.s`, or `prog.s`) |
| `testbench/` | the Verilog testbenches |
| `images/` | assembled memory images, regenerated by `run.sh` |
| `logs/` | `<test>.log`: full simulator output; `<test>.timeline.txt`: exceptions, TLB writes and halt (steps 3, 4); `summary.txt` |
| `README.md` | what the step is for, how the design works, what each test shows, and the result |
| `run.sh` | assembles the programs, runs the tests and writes the logs |

Shared by every step:

| Folder | Contents |
|---|---|
| `assembler/a.c` | the two-pass RiSC-16 assembler |
| `tools/lib.sh` | the helpers the `run.sh` scripts use |
| `tools/timeline.py` | turns a full-design simulation log into a list of events |
| `reference/` | Verilog-XL reference logs, `BOOT-log.txt`, and the course-provided memory images |
| `docs/design.md` | how the full `RiSC.v` works and what was filled into the course skeleton |
| `docs/findings.md` | every bug found along the way, and its status |

## How the steps build on each other

1. **Step 1** defines what correct results are, using the simplest possible hardware.
2. **Step 2** pipelines that hardware. The same program must produce the same registers and memory, so any difference is a pipeline bug.
3. **Step 3** adds the TLB, kernel mode and exceptions. It checks traps and translation first, then the one miss the kernel can resolve with a single physical load.
4. **Step 4** handles user misses. Their page-table walk can itself miss, so step 3's handler runs nested inside, and both handlers gain the saves and restores that make nesting safe.

The assembler is checked along the way: `run_all.sh` confirms the stage i and stage iii sources assemble to exactly the memory images that came with the course.
